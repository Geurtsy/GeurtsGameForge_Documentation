# Migration Guide: Geurts Documentation v0.11.0

**Version:** 0.11.0
**Status:** Non-normative target-release migration guide
**Required package path:** `Migrations/v0.11.0.md`

## Purpose

This guide records the planned transition to package v0.11.0 and the independent Geurts Documentation Companion contract schema 1.0.0. It is a checklist and target-release snapshot, not an integration, subject, or conflict authority. Follow `GeurtsTechniqueManifest.md` and its selected `GeurtsDocumentationCompanionTechnique.md` for current normative requirements.

## Target Architecture

The Geurts Documentation Companion is a small Windows-only, Editor-only Unity package installed into an already-existing Unity project through Unity Package Manager from its separate `Geurtsy/com.geurts.gameforge.documentation` repository. It has no dependency on any other Unity package, including Geurts Game Forge God, Odin Inspector, Quantum Console, or Game Forge Intelligence.

This documentation repository remains the sole generic-documentation source and contains no companion plugin code. It owns only the documentation package, the normative companion technique, and the closed schema-1.0.0 data contract. The companion package repository owns its Unity implementation and package-specific documentation.

There is no standalone Windows installer, external bootstrap, batch-driven installation, or separate setup action.

## Change from v0.10.0

Package v0.10.0 assigned documentation lifecycle behavior to Game Forge Intelligence and allowed that Update to replace only `GeurtsGameForgeDocumentation/`. Package v0.11.0 moves the lifecycle to the independent Documentation Companion and makes its one confirmed Update replace exactly five project targets:

```text
GeurtsGameForgeDocumentation/                                                     entire folder
AGENTS.md                                                                         entire file
.github/copilot-instructions.md                                                   entire file
.github/instructions/geurts-unity.instructions.md                                 entire file
.github/instructions/geurts-game-design.instructions.md                           entire file
```

The four AI files are copied directly from the exact existing template mappings in `GeurtsDocumentationCompanionContract.json`. Their complete prior contents are discarded. The companion does not merge managed regions, make backups, honor opt-outs, migrate legacy entries, or invoke the generic native-entry manager.

The documentation destination is now logically read-only managed content. This is not a Windows file-attribute requirement. Local edits remain physically possible, but they are unsupported and are discarded by the next confirmed Update without drift inspection.

Every normal Unity project launch/open may perform at most one non-blocking metadata-only request for the official repository's current `main` head commit. When performed, it compares that commit with one persistent companion-owned last-successful-installed commit value scoped to that Unity project and stored outside the Unity project filesystem and installed UPM package, such as host or Editor preference storage. The value is keyed without reading project content, and one project's value cannot suppress another project's update signal. A missing or differing value reports an Update available. No project file or project path stores that value. The value is comparison-only, non-authoritative, and not a receipt or recovery/compatibility state machine. Its write is attempted only after all five targets complete and verify successfully; a storage failure warns and may repeat the availability signal but does not invalidate successful managed content. The check does not download an archive, inspect managed project content, or mutate a managed target. A skipped check is non-blocking, and Update remains an explicit in-Editor action that never runs automatically.

## Release Transition Checklist

1. In Unity Package Manager, install the independent Windows-only, Editor-only Documentation Companion into the existing Unity project with **Add package from Git URL** and `https://github.com/Geurtsy/com.geurts.gameforge.documentation.git#codex/fix-bounded-metadata-check` while package pull request #2 remains unmerged. Keep the revision selector: the unqualified repository URL still selects the earlier package. Do not install or require God or Game Forge Intelligence for documentation management.
2. Remove or disable any older product-owned documentation startup check and Update UI so only the companion owns the lifecycle.
3. Select `Update Geurts Game Forge Documentation` in the Unity Editor and review the one cancel-default confirmation. Cancel must perform no Update network or filesystem work.
4. After confirmation, expect the companion to resolve and download an archive for the exact official `main` head commit, perform basic candidate validation, replace the complete documentation directory, and then replace the four exact AI files from the validated candidate templates.
5. Confirm that the resulting documentation directory contains the complete selected archive tree without Git metadata or a continuing source connection.
6. Confirm that all four AI targets exactly match their mapped templates and that no unlisted file inside `.github/` or `.github/instructions/` changed.
7. Confirm that the companion attempts to write its comparison-only last-successful-installed commit value only after the documentation directory and all four AI targets verify successfully, and treats persistence failure as a warning rather than a failed content replacement.
8. Confirm that the companion did not inspect or modify `Docs/GameDesign/`, run a documentation or project script, create project folders, scaffold GDD content, maintain a GDD manifest, provision `.gitignore`, or perform any other setup.
9. If any post-confirmation managed-target step fails or is interrupted, treat the operation as failed even if some targets changed. Invoke the same explicit Update again; there is no backup, rollback, journal, quarantine, repair, migration, or recovery path.
10. Verify all four route files tell agents to read `GeurtsGameForgeDocumentation/AGENTS.md` before planning or modifying any Geurts Game Forge brick code, treat the installed manifest-selected documentation as source of truth for that work, and explain that only tools supporting the applicable native instructions or explicitly following `AGENTS.md` will receive that guidance.

## Closed Contract Boundary

`GeurtsDocumentationCompanionContract.json` is intentionally not a setup-plan engine. Consumers must use its one source, one documentation destination, required validation entries, exact Update UI values, and exactly four route mappings. Under schema 1.0.0, consumers reject unknown fields and any changed or expanded managed destination, confirmation target, or route mapping. A later valid `packageVersion` and safe archive-root-relative `validationEntries` remain forward-compatible when the package version matches the same archive's manifest. Consumers never discover scripts or infer extra work from the repository tree.

The companion copies the documentation tree as inert content. It never executes `.bat`, `.cmd`, `.ps1`, or other files found in either the downloaded documentation or the Unity project.

## Validation

Validate package v0.11.0 on Windows PowerShell 5.1 and PowerShell 7. Current validation should establish that:

- the manifest selects the companion technique and contract from the same package commit;
- the JSON parses as schema 1.0.0 and package 0.11.0 with the exact official source, destination, action label, cancel behavior, validation entries, five confirmation targets, and four route mappings;
- every validation entry and mapped template exists at its exact registered package path;
- the companion contract contains no script discovery, batch execution, setup action, GDD access, or unlisted project target;
- supporting documentation no longer assigns the active lifecycle to Game Forge Intelligence; and
- both validation engines report current results rather than relying on historical counts.
